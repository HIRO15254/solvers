# HU Postflopから始めるクラウド費用の概算

作成・料金確認: **2026-09-20**。対象方針は[product roadmap](../product-roadmap.jp.md)。
利用者はクラウド・長時間の事前学習を許容し、予算は見積もりを見て判断する。
方針追記: **2026-09-21**。極端に重くない計算はローカル実行可。下記はクラウドが必要な場合の試験枠であり、初回着手の必須支出ではない。料金の再確認日は更新していない。

## 1. 今回判断できる費用

最初のHU Postflop基準計測には**約$55〜200**、その後の限定HU教師生成・ML実験には**別途約$355〜1,655**の資源枠を提案する。
これらは**公開単価と仮定した利用時間から計算した試験枠**であり、製品完成までの見積もりではない。
必要な教師数、目標精度に達するsolve時間、学習の収束時間は未測定である。税・開発工数は含めない。
今回、計算資源の契約や起動はしていない。

まず既存のローカルfixtureを整え、品質・メモリを確認したうえで、必要なクラウド計測量を絞る。
全バリアント・Multiway・ICM・profile付き学習の総額は、このHU計測だけから外挿しない。
汎用ゲーム境界の設計・小ゲームでの照合は初期から行うが、下表の学習費用は限定HUの資源枠である。
Multiway PostflopとPKOの低優先化を反映し、これらの学習費用を最初の枠に含めない。

## 2. 単価の根拠

長期契約・Spot・無料クレジットを見込まず、公開された従量単価を参照する。
CPUとGPUは役割に応じた比較用構成であり、採用事業者・リージョンは未決定。

| 用途 | 参照構成 | USD単価 | 一次資料 |
|---|---|---|---|
| CFR・教師生成の計算基準 | Google Cloud `n2-highmem-32`、32 vCPU、256 GiB、Iowa | $2.096224 / VM時間 | [General Purpose VM pricing](https://cloud.google.com/products/compute/pricing/general-purpose) |
| 小さい木の比較候補 | Google Cloud `n2-highmem-16`、16 vCPU、128 GiB、Iowa | $1.048112 / VM時間 | [同料金表](https://cloud.google.com/products/compute/pricing/general-purpose) |
| 小規模ML実験 | Lambda、1×A100 PCIe、40 GB VRAM | $1.99 / GPU時間 | [Instancesの1x欄](https://lambda.ai/instances) |
| 大きめの学習の規模例 | Lambda、1×H100 PCIe、80 GB VRAM | $3.29 / GPU時間 | [Instancesの1x欄](https://lambda.ai/instances) |

VM時間はvCPU時間ではない。32 vCPUのVMを4台×10時間使うと40 VM時間として数える。
GPUの欄は1 GPU構成であり、複数GPU構成の「GPU当たり単価」と取り違えない。
小さい木にはより小さいVMも候補になるが、CPU数だけからsolve速度を比例換算しない。
RAM/VRAM内に対象が収まることと、必要な時間内に解けることは別に測る。

永続保存の参照として、Google Cloud Storage StandardのIowaは$0.000027397 / GiB時間。
100 GiBを730時間保持すると約$2、インターネットへの転送は通常の最初の10 TiB帯で$0.12 / GiBとなる対象がある。
保存・転送・操作は別課金であり、たとえば100 GiBの対象転送なら$12が追加される。
VMの作業diskや別事業者への転送、リージョン差も実際の配置で積算する。[Storage pricing](https://cloud.google.com/storage/pricing)

## 3. 段階別の資源枠

以下の利用時間・その他費用・25%予備費は**本計画の仮定**であり、料金サイトが示した必要量ではない。
各行は別々の枠で、後の行に前段の費用を含めていない。

| 枠 | 32 vCPU / 256 GiBのVM時間 | 学習GPU時間 | 保存・作業disk・転送等の仮枠 | 25%予備費込みの概算 |
|---|---|---|---|---|
| HU基準計測（R1/R2の計測部分） | 16〜64 | 0 | $10〜25 | **$55〜200** |
| 限定HU教師・ML実験（R3） | 100〜500 | A100 40 GB: 24〜100 | $25〜75 | **$355〜1,655** |
| HUの学習領域を広げる規模例 | 1,000〜5,000 | H100 80 GB: 200〜1,000 | $100〜500 | **$3,570〜17,840** |

算式は`(VM時間 × CPU単価 + GPU時間 × GPU単価 + その他の仮枠) × 1.25`。
端点の計算値は順に$54.42〜198.95、$352.98〜1,652.64、$3,567.78〜17,838.90で、表は概算として切り上げた。
最後の行は拡張時の費用感を示す例であり、今すぐ確保すべき予算でも、Multiway完成に必要な額でもない。

最初の枠は、River / Turn / Flopの開始点、SRP / 3bet pot、ベット候補の粗密、rangeの広狭を変えた
少数の代表ケースで、初期化・CFR・BR評価・保存を含めた時間とpeak RSSを調べるためのもの。
2026-09-21の方針で、比較セットは日常5〜10件・大きな改造後20〜30件とする。[HU検証計画](../validation.jp.md)では8/24件を初案とした。
通常規模をローカルで測り、その中でクラウドが必要なケースの件数と時間から上の試験枠を再見積もりする。フルの教師集合の生成費用は含まない。

ML実験の枠ではRiverまたは限定Turnのvalue学習、条件を分けた検証、再solve後の品質測定を行う。
この時間で十分な精度に達するかは実験事項であり、合格が未達なら枠内の結果から継続・方式変更を判断する。
Flop全般、任意range、任意ベット木への汎化は別途検証する。

## 4. 教師生成で費用が変わる要因

教師1件は「board・両者range・stack/pot・ベット木・utility・抽象化を固定して解いた問題」を指す。
1件から多数のhand別labelが得られても、独立した問題がその数だけ増えたとは数えない。

1,000件を1 VMで順に解き、1件の初期化・solve・BR・保存の合計平均が次の場合、CPU費用だけでも差が出る。
これは計算式の感度例であり、実測時間や必要教師数ではない。

| 1件の平均時間の仮定 | 1,000件のVM時間 | CPU費用のみ |
|---|---|---|
| 1分 | 約16.7時間 | 約$35 |
| 10分 | 約166.7時間 | 約$349 |
| 60分 | 1,000時間 | 約$2,096 |

ここへ独立検証用データ、停止基準に届かなかった再計算、抽象化の比較、学習、保存等が加わる。
複数の小問題を同じVMで実行できる場合は、実測した合計throughputで換算する。
単純な「件数×1件の時間」と「並列化の理想倍率」を同時に使って費用を二重に下げない。

既存[development.mdのbench bar](../development.md)には特定のFlop木に対する45秒等の過去の受入目標があるが、
今回のクラウド、教師精度、広いrange・ベット木で確認した時間ではないため、この見積もりの実測値には使っていない。

## 5. 通常利用の継続費用

利用時の費用は`起動していた時間 × 単価 + 保存・転送等`で見積もる。
例としてA100の同単価なら、月30時間の起動で計算部分は$59.70、730時間の常時起動で$1,452.70となる。
これは同じ速度・品質を達成できるという意味ではなく、利用時間による費用差の例である。
Lambdaは実行中のinstanceに課金し、処理していない時間も含む。[Billing](https://docs.lambda.ai/public-cloud/billing/)

個人学習の初期運用では必要時の起動を候補にする。起動待ち・model読込も利用者の待ち時間として計測し、
数分の目標に対して常時起動が必要か、CPU推論や小さいGPUで足りるかを比較する。
通常利用と学習用に同じGPUを必須とはしない。

## 6. 次の見積もりで確定させるもの

1. HUの小さい照合ケースと実用ケースで、CFR残差・抽象化感度・peak RSS・全工程時間を確認する。
2. 対応範囲を固定し、教師問題数、検証用の分割、再計算率、保存するlabelと容量を見積もる。
3. 小さい学習で必要VRAM、batch throughput、局所solveまで含む精度・速度を測る。
4. その結果から、少量試験・限定HU実用版・次の領域拡張の費用を再提示し、利用者が段階ごとの上限を決める。

料金の確認日、リージョン、source/binary/model、利用時間、品質合否、保存と転送を同じ実験記録に残す。
金額はUSDで示し、日本円決済時の為替・手数料・税は判断時に加える。
