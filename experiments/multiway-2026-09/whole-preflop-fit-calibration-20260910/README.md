# 全プリフロップ逸脱fitの計算量校正

**評価用fitを16倍に増やすと正の利得を検出する例が現れたが、全体の比較に十分な候補はまだ得られていない。**
131072 traversals/席で24組中6組のmeanが正となり、pointwise 95% CI下限が正なのは
seed 2802のUTG・両探索方式の2組だった。18組はmeanが負、8組はCI上限も負である。
8192 traversals/席の初回では全24組のmeanが負だった。別の検証seedを使っているため、
予算間の差をpaired差分や同時保証として扱わない。

元の学習済み戦略、全Preflop census、旧診断は完全に再現した。変えたのは評価側のfit予算と
未使用のheld-out seedだけである。これは評価用候補の検出力の校正であり、
ソルバー戦略の品質向上やレイズ後列挙の優位性を示す結果ではない。

## 比較条件

同じcandidate-v3 executableを使い、通常探索とレイズ後列挙を順に実行した。
学習条件は6max、100bb、部分Simple fixture、EHS² K32、range-vector、seed 0、
8192 sweeps、batch 4、8 threads、8 GiB設定。warm cache、processごとのtimeout 600秒。
fit seed 2601は維持し、fitを8192→131072回/席へ増加した。初回fit列は長いfit列のprefixになる。
検証は32768 worlds/seed、初回の2701/2702から未使用の2801/2802へ変更した。
初回結果を受けた追加実験であり、その予算とseedは新結果を見る前に固定した。

本人の全Preflop判断を変更し、相手・本人Postflop・未採用keyはbaselineを維持する。
8 fit visitsの採用閾値と最大4096 sample結果のbufferは変更しない。全sampleを分母とし、
負gainをclipしない。GCP resourceは開始していない。

## 次の改善と限界

多くの席で依然として負利得となるため、このfitを用いたsampler順位付けは保留する。
単なる反復数増加に加え、固定profileに対するfitの実装と分散を調べる。
学習側で既に用いているrange-vector評価など、同じ計算費用でより強い評価候補を
得る方法を独立oracleと固定held-outで検証する。負値だけから原因を断定しない。
公開metadataから選んだ12 endpointは全acting位置・call後multiway・深いreraiseを
補う予定だが、この校正自体はroot-weighted評価である。limpなしのfixture、
部分的なGTO Wizard参照、一つの学習seed、研究samplerのcheckpoint/resume未対応も残る。
目標全体は継続中である。
