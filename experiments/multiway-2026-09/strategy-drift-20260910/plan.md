# Production strategy-drift storage

Status: implementation, seven verification commands and all six serialized
measurements completed. Final summary regenerated byte-identically; all output
checkpoints matched byte-for-byte. See the
[validated report](plan.md).
2026-09-10.

The production loop retained a `HashMap<InfoKey, Vec<f32>>` containing the
previous normalized profile even with dense policy storage. The core already
provides `StrategyDriftTracker` and `strategy_drift_refresh_compact`; production
now uses them at initialization and at all three evaluation boundaries.
Error results receive context and propagate instead of silently resetting.
The tracker is still dropped before solution staging.

This integration changes no learning updates, RNG, metric definition, artifact
format or configuration default. Dense storage keeps two u32 values per
observed column and a contiguous f32 probability buffer. Sparse storage still
uses the legacy map. Growth can temporarily hold both old and new buffers;
per-column normalization still allocates a temporary vector. The retained
payload counter omits allocator overhead and is not a process memory cap.

## Measurement boundary

separate processes:
legacy-1, compact-1, compact-2, legacy-2, legacy-3, compact-3, each with a
300-second timeout. It used the same K32 checkpoint/config as the writer cohort,
8 threads, 8GiB, and the existing warm cache. First capture and stable refresh
had identical per-seat f64 bits and stored-column/action-slot counts.
The example inspects shape counts between those two timed calls. Both methods
drop their tracker and save through the same borrowed checkpoint writer.
Every output byte matched. Raw fields matched after excluding mode, output
path, the three elapsed clocks and retained payload bytes.
All trials are retained with descriptive medians and no confidence interval.
Initial capture median fell 0.6433555 to 0.1534594 seconds; stable refresh fell
0.5959598 to 0.1473973 seconds. Retained capacity payload fell 237,627,888 to
49,512,632 bytes. Whole-process lifetime peak stayed about 1.95GB, while session
construction dominated total time. No phase RSS, changing-profile growth,
hard memory-cap or learning-speed claim follows. No GCP allocation was made.
