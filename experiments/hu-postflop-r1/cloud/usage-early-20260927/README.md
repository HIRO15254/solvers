# 初期4台の使用量と費用余裕の再計算

2026-09-27 03:04:59–03:05:05 UTC に、既存の VM02/05/06/07 の Monitoring
送信バイト数と uptime を読み取った。8 GET はすべて HTTP 200。作成・削除の証拠と
取得時の予算台帳を [inputs](inputs/) に元バイトのまま保存し、
[acquisition.json](acquisition.json) に要求、応答、SHA-256 を記録した。
トークンはメモリ内だけで使用し、資源・予算・認証設定を変更していない。

以下は通常料金と余裕を用いた**使用量ベースの仮定付き見積もり**であり、実請求や保証上限ではない。
合計 **$17.6663** を $18 に切り上げて保持するなら、従来の $20 のうち **$2** が再利用候補になる。
この資料自体は予約を解除しない。

名前はいずれも `solvers-r1-20260925-{VM}`、project は
`solvers-abstraction-20260723`、zone は `us-central1-b`。
表の USD は小数6桁へ切り上げた表示で、計算は [report.json](report.json) の Decimal 値を使う。
費用用全期間は作成要求時刻から削除完了またはその後の不在確認までを秒単位で切り上げ、
STOP 時間を差し引かない。正確な各時刻と証拠の区別も同 JSON にある。
02/05 は当時の削除・不在確認記録であり、その時点の生の list 応答は今回の資料にはない。
06/07 は retained delete operation の DONE と、その後の空の資源確認を照合した。

全4台は E2 highmem 8、100 GiB 自動削除ディスク各1台。費用は次を合算した。

- 計算資源: 全期間計14,024秒 × $0.37/時。Iowa 通常料金 $0.36159864/時を上回る台帳の丸め値を維持し、Spot 割引・クレジットを使わない。[公式料金表](https://cloud.google.com/products/compute/pricing/general-purpose)
- IPv4: 同じ全期間 × $0.0025/時。
- ディスク: 4 × 100 GiB × 24時間 × $0.000137/GiB時 = $1.3152。
- 転送: 各台2 GiB × $0.30/GiB = 合計 $2.40。観測合計149,960,905 bytesより大きい余裕だが、欠測分の数学的上限ではない。
- 元の other reserve: $3.2/$3.2/$3.2/$2.9、合計 **$12.50を全額保持**。税・為替・遅延等をゼロと仮定しない。

ディスク・ネットワーク料金の新しい取得資料は
[preflight-vm14/pricing-sources.json](../preflight-vm14/pricing-sources.json)、元の丸め単価は
[保存台帳](inputs/budget.json) にあり、参照バイトの SHA も report に残した。
計算資源の公式表は Web tool の表示で確認したもので、ページ全文の取得証拠ではない。

Monitoring は請求の完全性を示さない。内部欠測は02送信の約1分、06送信の約2分、
06 uptime の約1分と約2分。作成直後・削除直前の端も網羅されない場合がある。
1 ms の通常の区間境界と、それ以上の欠測を区別した。未観測バイト・時間・実請求は `null`。
観測 uptime のみで同じ余裕を加算すると $17.5901 だが、これは下限・上限のどちらの保証でもなく、
再利用候補の計算には全期間の $17.6663 を使用した。

元の [費用監査](../cost-audit-20260925/audit.json) を書き換えず、新たな使用量ベース見積もりの
許可に対する別の計算として保存した。既存の
[資源不在確認](../usage-reconcile-20260927/inventory-check.json) はその取得時点の証拠であり、
今回進行中の別 VM の費用・使用量はこの4台へ混ぜない。

再検算はネットワーク不要で、次の小さなコマンドだけで行える。

```text
C:\Python313\python.exe -B experiments/hu-postflop-r1/cloud/usage-early-20260927/analyze.py
```

[checks.json](checks.json) は最終コマンド、終了値、前後の source pins、出力 pins を記録する。
API 再取得を行う `collect.py` と、保存応答だけを読む `analyze.py` は別である。
