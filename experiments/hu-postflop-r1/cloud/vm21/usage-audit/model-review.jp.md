# VM21 使用量再評価の計算方針

取得前のレビューであり、返還提案・請求確定額・台帳変更ではない。元の予約は `../reservation.json` と `../budget-proposal.json` の $1.35。

再評価する場合も、2 vCPU は元の45分全枠に120秒を加えた47分、32 vCPU は元の8分全枠に120秒を加えた10分を重複して保持する。実測 uptime による割引、停止中時間の控除、Spot 単価への変更は行わない。IPv4 も元の47分を維持する。

変更候補は20 GiB disk の24時間保持枠だけ。同じ disk ID・作成時刻・接続先 VM、成功した delete、削除後の disk 不在を原本で確認し、作成から不在確認までの秒数に120秒を加え、分単位で切り上げる。実期間が24時間枠を超える場合は縮小しない。

保持する式は次の通り。

```text
disk_minutes = ceil((confirmed_disk_lifetime_seconds + 120) / 60)
model_usd = 47/60 × .06701142
          + 10/60 × .80
          + 47/60 × .0025
          + disk_minutes/60 × 20 × .000137
          + .3125 × .30
          + 1.00
hold_usd = ceil(model_usd / .05) × .05
```

元の320 MiB転送枠と $1.00 の不確実性予備費を削減しない。転送 intent は開始済み失敗分・不確実分も全額残し、Monitoring の送信バイト合計と照合する。観測値または開始済み転送＋64 MiB制御通信枠が320 MiBを超えた場合は、この式のままで返還しない。Monitoring が欠落する区間は0と扱わず、元の通信余裕と不確実性予備費を維持する。

取得した uptime と送信量が対象 VM に結びつくこと、元の STOP と32 vCPU短縮 STOP が記録通りであること、2→32→2以外の起動・変更がないことも検査する。使用量を取得できない場合や原本と食い違う場合は、返還提案を保留する。

24時間からディスク実期間だけを短縮した結果、保持額が1時間未満の通常ケースで $1.30 となる見込みはあるが、削除・取得・検査前には確定しない。$0.05単位の上方丸めはVM19/20と同じ規則であり、利用可能予算に合わせて変更しない。実際の請求額は別途 Billing の根拠が必要で、ここでは不明のままとする。
