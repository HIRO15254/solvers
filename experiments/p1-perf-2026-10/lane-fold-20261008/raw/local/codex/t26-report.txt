B: separate kinds
River folds with batch_tables != u32::MAX always use the fold-only specialization. Showdowns always use the rank sweep. Sort by (table, caller index), then filter showdowns and folds separately; each kind fills batches of up to eight, with indices increasing.
Fold kernel interleaves reaches, makes one ranked-opponent compatibility-sum pass and one live-own pass: u_fold * (total - card[a] - card[b] + identical_reach). Utility-last matches the algebra of the lone fold kernel and avoids cancellation in utility-scaled sums; rank-order versus combo-order sums may round differently.
No rank-group control flow in fold specialization, no zero-reach branches in hand loops, no allocations after worker-buffer warm-up/growth. Missing tables, earlier folds, runouts and f64 keep T25 fallback.
Initially sorted (table, kind, caller index). Replaced with table sort plus two linear filters to avoid reordering the usual single-table subtree. In grouping.json, median paired filter/kind-sort ratios were:
  nine: 0.9754 (large timing shifts; larger workloads effectively tied)
  btn_bb: 1.0030 (large timing shifts; larger workloads effectively tied)
  wide: 0.9950 (large timing shifts; larger workloads effectively tied)
A alone is the measured mixed fold/showdown sweep alternative. Final B always splits kinds to preserve the kind-specific rounding rule; no conditional fold-fill policy was retained.

Buffers and linked executable audit
Thread-local reach Vec: (opponent_support+1)*L floats; last row is +0 sentinel, ABSENT lookup uses min(opp_len). Thread-local values Vec: own_support*L floats. Vectors retain high-water length/capacity; only active prefixes are touched. Dead-row list is per table/seat, u16 per dead local. Group index Vec reuses worker capacity; selected batch indices use 8 usize stack entries.
Active reach+value bytes = 4*(own_support+opponent_support+1)*L: BTN/BB 27,168 atL8, 16,980 atL5 and13,584 atL4; wide69,216 atL8. Common Flop1 supports479/436: T25L8=29,312, new showL5=18,320/foldL4=14,656. Values remain interleaved; direct-store variant alone drops them.
Stack card sums =52*L*4 bytes (1,664B atL8), plus lane vectors and output refs. Width-specific functions stay uninlined so small batches do not reserve width8 frame.
filter-kernels.exe and required t26-p1_bench.exe both audited with llvm-objdump and PE unwind function bounds. PDB symbols locate eval_cfr_batch; PE call graph locates private width specializations.
width8 showdown: bench0x1401449e0..0x1401478fd / p1 0x14003b470..0x14003e38d, stack reservation0xd58=3416B; fold: bench0x140147900..0x140149409 /p1 0x14003e390..0x14003fe99,0x878=2168B (excluding pushed registers and nested callee frames).
Fold own loop has two YMM vsubps, one vaddps, one vmulps and one full-width interleaved store; shared opponent helper has YMM arithmetic. Showdown lane arithmetic stays vectorized.
Chosen width8 main output loop loads eight strided scalars and stores eight adjacent scalars with the output pointer retained per row. It does NOT use a full-width store for these blocks; the small tail uses masked gathers/stores. Full-matrix variant instead has unpack/shuffle/permute and YMM stores, stack0xde8=3560B. Direct variant frame0xa88=2696B, but own-loop arithmetic scalarized. Index safety checks remain for local/card gathers; lane arithmetic and block copies have no per-lane bounds checks.
