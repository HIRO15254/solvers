# P1 目標到達の評価間隔の模擬（2026-10-08）

状態: 模擬完了。利用者決定PF10の根拠。

問い: Exploitabilityを評価する間隔を、目標までの距離に応じて変えると、0.1% potまでの時間はどれだけ縮むか。

関連は[P1性能計画](../../../docs/plans/p1-performance.jp.md)第3節（T15）、Linear SOL-15。
再現状態は`verified`。記載scriptを保持データに対して再実行し、[result.json](result.json)を得た。

## 背景

P1は`[solver.stop] check_every`（既定25）iterationごとにExploitabilityを評価し、`NashConv / 2 <= target`で止まる。
評価1回のコストは、GCP c2d-highcpu-32・32 threadsで次のとおりである（[T9・T10受入](../accept-t9-t10-20261007/README.md)のbench）。
- f32: 1 iterationの1.09〜1.14倍
- i16-f32avg: 1 iterationの0.83〜0.90倍

固定25の評価間隔には、次の2つの無駄がある。
- 評価そのもの: 約4.4%
- 目標を越えてから次の評価で止まるまでの超過: 平均約12 iteration

## 条件

- 入力は[DCFR係数の掃引](../dcfr-pdcfr-20261007/README.md)が保持する収束曲線（`raw/`）である。
  - GCP 32 threadsのsweep1〜4、gtow_bのrun（`conv/`）、手元の旧i16 run（local J）。
  - 10の木、3 storage、複数のDCFR係数を含む131本。
  - 0.1% potに届かない曲線は除いた。
- 検査点（`check_every` 5〜25）の間はlog-logで補間する。目標は0.1% potである。
- 費用の単位は1 iteration。評価1回をE iterationとし、E = 0.9・1.1・1.3で比べた。
- 比較の基準は固定25（費用 = 停止iteration＋E×評価回数）。
- 適応方式（採用案）:
  - 最初の評価は25。履歴が2点未満なら25 iteration後に評価する。
  - 直前2回の評価(t0, v0)、(t1, v1)から傾きs = ln(v0/v1) / ln(t1/t0)を求める。
  - s > 0.05なら、到達予測t* = t1 × (v1/target)^(1/s)の8割の地点、step = ceil(0.8 × (t* − t1))で次を評価する。それ以外はstep = 25。
  - stepは[3, 50]に収める。
- scriptは`scripts/simulate.py`（引数無しで保持データを読み、`result.json`を書く）。

## 結果

E = 1.1での費用比（固定25 = 1、131本）:

| 方式 | 平均 | p90 | 最悪 |
|---|---:|---:|---:|
| 採用案（0.8、最小3、最大50） | 0.957 | 0.987 | 1.004 |
| 最大25（他は同じ） | 0.972 | 1.004 | 1.018 |
| 0.9、最小3、最大100 | 0.952 | 0.977 | 1.151 |
| 固定10 | 1.037 | 1.063 | 1.100 |
| 固定50 | 1.012 | 1.088 | 1.119 |
| 理想（到達点で1回だけ評価） | 0.925 | 0.957 | 0.961 |

- Eを0.9〜1.3で変えても、採用案の平均は0.955〜0.959で、順位は変わらない。

## 判断

- 利用者決定PF10（2026-10-08）: `check_every`に`"auto"`を足して既定にし、targetのあるrunを採用案で評価する。
  - targetが無いrunは固定25のまま。整数を明示すれば従来どおりの固定間隔。
  - 中断・`max_time`・定期checkpointの判定は25 iteration以下ごとに行う。
  - 停止iterationが旧版と変わり得る。目標を満たすことは変わらない。
- 実装はT15で行う。実solveでの短縮はT15の受入で確かめる。

## 限界

- 補間した曲線での模擬である。検査点の間にあるDCFRの一時的な悪化は見えない。
- 評価のコストは木と並列度で変わる。上の比較はEを一定と置いた。
- 費用は計算量の比である。checkpointや`.sol`の保存時間は含まない。
