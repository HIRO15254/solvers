Implementation:
  TerminalEvaluator::eval_cfr_batch defaults to one eval_cfr per terminal. Existing CFR pass is untouched.
  PostflopEvaluator precomputes eligible table IDs for showdowns and complete-board folds without altering existing terminal metadata.
  A reusable thread-local Vec of caller indices is sorted by table and split into batches of up to eight.
  Earlier-street folds and terminals without one table fall back to eval_cfr. f64 precision always falls back.
  The current model expands all-in runouts into chance edges and single-board showdowns; there is no aggregate all-in terminal to batch.
  Kernel worker-local Vec<f32> buffers use active prefixes: (opponent_support+1)*L reaches, own_support*L values.
  Length/capacity high-water marks are retained; only first use/growth allocates/initializes. Each call overwrites reach rows and clears its sentinel.
  Values are written/read only for ranked own hands. Actual output slices are cleared to preserve positive-zero board-dead entries.
  Scratch active prefixes at L=8: BTN/BB 27,168 B (26.53 KiB), wide 69,216 B (67.59 KiB). This excludes caller inputs/outputs.
  Grouping index prefix is eight bytes per eligible requested terminal on this x64 host (high-water capacity retained).
  Stack uses 52*L*4 B of card sums plus lane vectors. Linked width-1 frame=424 B, width-8=2904 B; evaluator entry=552 B plus saved registers.
  Widths 1..8 are specialized with inline(never) to avoid reserving the eight-lane frame on singleton calls. Batch path stack total is under 4 KiB.
  One total accumulator per lane, no reach-dependent branches in per-hand loops, safe Rust only.
  Tied hands are reread for the win-minus-tie update, avoiding a 52*L group reset/merge. Interleaved output is transposed to caller slices.
