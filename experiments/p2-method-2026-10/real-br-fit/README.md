## 方法

`mw_preflop::trunk::l0::real::fit_real_responses`（実験用、製品契約の外）は、入力のゲームの配札で、class profileに対する
seatごとのclass単位の最適応答を求める。配札は[L0の誤差の測定](../l0-real-check/README.md)と同じく`DealSampler`で引く
（全seatの手札が重ならず、5枚のboardはfoldしたseatを含む全員の手札を除いた山から引く）。

- fit用の配札（配札のseed 1）で、seat `i`・class `c`・終端`z`ごとに重み`W_i[c][z] = Σ_d 1[c_i(d) = c] Π_{j≠i} π_j(z) U_z[i]`
  を足す。`π_j(z)`はseat `j`の手札のclassでprofileの行動確率を経路に沿って掛けたもの、`U_z`は終端`z`の精算（chip EV）である。
  seat `i`・class `c`ごとに木を下から辿り、seat `i`の決定点では部分木の重みが最大の行動（同じなら番号の小さい行動）を選ぶ。
  こうして決めたclass単位の純粋な戦略（以下、純粋な応答）は、fit用の配札の上でのclass単位の最適応答である。
- 入力のゲームでのseat `i`のclass単位の利得を`g_i^real`と書く（`NashConv^real = Σ_i g_i^real`）。純粋な応答のfit用の配札での
  利得（in-sample）は、標本の上で最大を選ぶので上に偏り、期待値で`g_i^real`以上である。純粋な応答を独立な評価用の配札
  （配札のseed 0）でS4-1a2の`evaluate_real`により評価した利得（held-out）は、決まった戦略の利得の不偏推定なので、
  期待値で`g_i^real`以下である。L0の最適応答を評価用の配札で使った利得（S4-1a2で測った量）も、同じ理由で下限である。
- データの少ないcellでは、純粋な応答は雑音に従って行動を選ぶ。profileがすでに良い行動を選んでいるcellでは、雑音で選んだ
  逸脱はprofileより悪い。そこで閾値`z`ごとに、逸脱を絞った応答（以下gated）も求める。seat `i`の決定点(node, class)で、
  最良の行動`a*`の部分木の値`V(a*)`と、profileの行で混ぜた値`F = Σ_a σ(a) V(a)`の差`A = V(a*) − F`を求め、
  `A > z·SE`のときだけ`a*`へ逸脱し、そうでなければprofileの行に従う（`FOLLOW`）。`V`は下の決定点での選択を反映した値である。
- `SE`はlaneから見積もる。fit用の配札を4096配札の塊に分け、lane `ℓ`に塊`ℓ, ℓ+16, …`を割り振って、重みを16本のlane別にも
  足す。laneごとの差`A_ℓ`から`SE = sqrt(16/15 · Σ_ℓ (A_ℓ − Ā)²)`とする。1つのlaneにしかデータの無いcellでは`A = SE`になる
  ので、`z ≥ 1`では逸脱しない。laneを標本とみなすので、fit用の配札が16×4096以上のときに意味を持つ。
- gatedの応答もfit用の配札だけで決まるので、そのheld-outの利得も`g_i^real`の下限の不偏推定である。gatedのin-sampleの値は
  profileの値と純粋な応答の値の間にあり、`z = 0`では純粋な応答と同じになる。
- 応答の組（L0の最適応答、純粋、z = 1・2・3）は同じ評価用の配札で評価する。いくつかの下限から最大を選ぶと、選んだ分だけ
  上に偏る。
- `±`は配札ごとの値の標本標準偏差を√Nで割った標準誤差。fit用の重みはlaneごとに塊の順に足し、全体はlane 0から順に足すので、
  結果はthread数に依らない。

## 検査

- `fit_matches_evaluation_on_the_same_deals`: 3人・4人の木、乱数のprofile、3,000配札で、純粋な応答の値・profileの値・利得が、
  同じ配札での`evaluate_real`と一致する（相対1e-9）。到達しないclassは各決定点で最初の行動を選ぶ。
- `fitted_responses_are_optimal_on_the_fitting_deals`: 純粋な応答の、seatごとに1つの(node, class)の行動を別の行動に変えた
  30通りと、L0の最適応答・乱数の応答2つを同じ配札で評価し、どれも純粋な応答の値を超えない。
- `gated_pass_matches_recursive_reference`: gatedの選択（行動と値）を、laneごとの値を再帰で辿る参照実装と比べる
  （3人の木、z = 0・1・2・10⁹）。重みが全部0なら逸脱せず、1つのlaneにだけ重みがあれば`z ≥ 1`で逸脱しない。
- `gated_responses_match_evaluation_on_the_same_deals`: 3人・4人の木、16×4096配札、z = 0・1・2・10⁹で、gatedの値が同じ配札での
  `evaluate_real`と一致し、profileの値と純粋な応答の値の間に入る。z = 0は純粋な応答と同じ値、z = 10⁹は逸脱が無く
  profileと同じ値になる。z = 1の逸脱はz = 0より少なく、0より多い。
- `all_follow_has_exactly_zero_gain`: 全cellが`FOLLOW`の応答の利得はbitで0。
- S4-1a2の`physical_deal_values_match_independent_recursive_settlement`に、約30%のcellが`FOLLOW`の応答を加えた
  （配札ごとに参照実装と許容差1e-12で一致）。
- `fitted_responses_are_thread_independent_and_validate_inputs`: thread数1と4で、純粋・gatedの応答と値がbitで一致する
  （16本のlaneを全部使い、lane 0に2つ目の塊があり、最後の塊が端数）。閾値の誤り（負、NaN、無限、5つ以上）、配札数1、
  gameとtree・profileの不一致を拒否する。
- ignoredのrelease test `fitted_responses_match_l0_in_heads_up`: 2人10bb、乱数のprofileで、2^20配札（seed 1）でfitし、
  別の2^20配札（seed 2）で評価する。純粋な応答とz = 2のheld-outの利得がL0の厳密な利得＋5標準誤差以下、純粋な応答の
  in-sampleの利得がL0の厳密な利得−5標準誤差以上。

## B1: 2人push/fold

2人ではL0が入力のゲームそのものなので、L0の利得`g_i`が入力のゲームでのclass単位の利得そのもの（厳密な値）になる。
held-outの利得は期待値で`g_i`以下、純粋な応答のin-sampleの利得は期待値で`g_i`以上になるはずである。
[L0の誤差の測定](../l0-real-check/README.md)のB1と同じ9件（5・10・20bb × 一様・乱数・暫定方式の解）で、2^22配札
（配札のseed 1）でfitし、S4-1a2と同じ2^22配札（seed 0）で評価した。fit用の配札では、L0の最適応答も評価した
（`<case>_fit_deals.json`）。表は[results/b1/summary.md](results/b1/summary.md)にある。

- S4-1a2で測った量（seatの値、`k`別の値、L0の最適応答の値と利得）は、9件ともS4-1a2の結果とbitで一致した。
- held-outの利得: fitした応答（純粋、z = 1・2・3）がL0の厳密な利得を上回った幅は、最大+1.19標準誤差だった
  （L0の最適応答は+1.84）。上限と矛盾しない。
- fit用の配札の上では、純粋な応答のin-sampleの利得はL0の最適応答の利得以上だった（差の最小は−8.9×10⁻¹⁶で、丸め誤差）。
  profileのin-sampleの値は、fit用の配札での`evaluate_real`の値と1.4×10⁻¹⁵以内で一致した。
- 純粋な応答のin-sampleの利得 − L0の厳密な利得は−0.0031〜+0.0036で、負の値もあった。上限は期待値についての主張なので、
  1回のfitでは配札の揺れの分だけ下回り得る。この差を2つに分けた。
  - fit用の配札の揺れ（L0の最適応答のfit用の配札での利得 − 厳密な利得）: −2.9〜+1.6標準誤差。
  - 選択の偏り（純粋な応答 − L0の最適応答、どちらもfit用の配札）: 一様・乱数のprofileで0.0002以下、
    暫定方式の解で0.0001〜0.0017。
- 暫定方式の解は、L0の利得が0.0002〜0.0018と小さい、均衡に近い解である。ほとんど無差別なcellが多いため、選択の偏りが
  利得と同じ大きさになった。fitした応答のheld-outの利得も、どのseatでもL0の厳密な利得を下回った（−0.80標準誤差以下）。
  例えば10bbのBTN/SBでは、厳密な利得0.0010に対して、純粋な応答はin-sample 0.0016、held-out 0.0002だった。
  均衡に近い解では、fitした応答で上下から挟む幅が利得に比べて広い。
- 逸脱したcell（338のうち）: 一様・乱数のprofileでz = 1が329〜336、z = 3が313〜328、暫定方式の解でz = 1が86〜121、
  z = 3が69〜86。

## B3: 暫定方式の20bb解

2^24配札（約1,678万、seed 0）で評価した。L0の節は4つともS4-1a2の結果とbitで一致した（S4-1a2は2^25配札で評価したので、

- 入力のゲームでの`NashConv`は、期待値でL0の最適応答の利得の和（下限）と純粋な応答のin-sampleの利得の和（上限）の間にある。

- 範囲の幅は0.044〜0.050 bbで、解の良し悪しにほとんど依らない。純粋な応答のin-sampleとheld-outの差も0.068〜0.079で、
  4つの解でほぼ同じだった。どちらも主に、fit用の配札の雑音に合わせて行動を選ぶ分である。30kの解では利得が大きいので
  幅は比で±7%程度だが、300kの解では幅が利得と同じ大きさになり、この配札数ではL0の`NashConv`が妥当かを判定できない。
- 逸脱したcell（自分の決定点のcell 923,754のうち）: 30kの解でz = 1が57.7万・57.7万、z = 3が16.4万・17.5万、
  300kの解でz = 1が47.7万・47.3万、z = 3が4.2万・4.0万。

最初の部分）、評価用の配札（2^24、seed 0）は同じである。

seatの利得の和（in-sample → held-out ± 標準誤差）。L0の`NashConv`は0.0531、L0の最適応答の利得は0.0318 ± 0.0011。

## 解釈

- L0の`NashConv`は、入力のゲームでの`NashConv`（class単位）と同じ大きさを示した。30kの解では入力のゲームの値の範囲
  （L0の値の0.91〜1.06倍）に入った。`20bb_300k_s0`では入力のゲームの値が0.040〜0.044に絞られ、L0の0.053はその1.2〜1.3倍だった。
  30kの2つの解から`20bb_300k_s0`への減り方は、L0で1/6.5・1/6.7、入力のゲームで1/7.1〜1/9.3・1/7.5〜1/9.5で、
  解の順位は同じだった。
- L0が高く見積もった分（約0.009〜0.014 bb）は、blindとBTNに集まった。S4-1a2でL0がseatの値を最も高く見積もったのもBBだった。
- P2D1（L0の`NashConv`を主な指標にする）と矛盾する結果は無かった。30kと300kの解の比較では、L0の`NashConv`が小さい解ほど
  入力のゲームの`NashConv`も小さかった。ただし、L0は入力のゲームの`NashConv`を0.01程度高く見積もり得る。また、L0の`NashConv`が
  0に近い解で入力のゲームの`NashConv`がどこまで下がるか（L0の誤差が決める下限）は、まだ測っていない。S4-1bでL0の
  `NashConv`が暫定方式の解より小さいB3の解ができたら、同じ方法（2^27配札のfit）で入力のゲームでの範囲を測る。
- 範囲を絞る費用は大きい。300kの解の範囲を幅0.005に絞るのに、fit用の配札2^27（fitに71分）が要った。範囲の幅は配札数に
  ほぼ反比例して縮んだので、幅を半分にするには配札がおよそ2倍要ると見込まれる。この方法はcheckpointごとの指標には使えず、節目の確認に使う。

## 時間

- B1: 1件あたり1〜3秒（fit、評価、fit用の配札での評価の合計）。2^22配札のfitは0.29〜0.48秒だった。
- B3のfit（16 thread、2^23配札）: 30kの解は688秒・577秒（毎秒約1.2万・1.5万配札）、300kの解は242秒・186秒
  （毎秒約3.5万・4.5万配札）。S4-1a2の評価と同じく、到達確率0の部分木を飛ばせる量で速さが変わる。
- B3の評価（2^24配札、5組の応答）: 30kの解は1,389秒・1,128秒（毎秒約1.2万・1.5万配札）、300kの解は195秒・151秒
  （毎秒約8.6万・11万配札）。応答を1組だけ評価したS4-1a2（300kで毎秒約23万・31万配札）より遅い。
- 同じprocessでのL0の評価は61〜85秒。B3の1本は、fit用の配札が2^23以下で401〜2,142秒、2^25・2^27配札で1,380秒・4,504秒。
- fit用の配札数を変えた`20bb_300k_s0`のfitは、2^21配札で81秒、2^25配札で1,085秒、2^27配札で4,245秒
  （毎秒約2.6万・3.1万・3.2万配札）。fitの時間は配札数にほぼ比例する。8 threadでの評価し直しは全体で427秒
  （16 threadでは408秒）。
- B3の記録した8本の合計は11,533秒（[run_b3.log](results/b3/run_b3.log)）。中断された1本の分は含まない。

## 手順

workspace rootでGit Bashから実行する。

```sh
cargo build -p mw-preflop --release --example l0_real
bash experiments/p2-method-2026-10/real-br-fit/run_b1.sh <B1の出力directory>
bash experiments/p2-method-2026-10/real-br-fit/run_b3.sh <B3の出力directory>
python experiments/p2-method-2026-10/real-br-fit/summarize.py b1 <B1の出力directory> experiments/p2-method-2026-10/l0-real-check/results/b1
python experiments/p2-method-2026-10/real-br-fit/summarize.py b3 <B3の出力directory> experiments/p2-method-2026-10/l0-real-check/results/b3
```

- [run_b1.sh](run_b1.sh)は、[L0の誤差の測定](../l0-real-check/README.md)の乱数のprofile（`results/b1/`）と表のcache
  （`.cache/p2-trunk`、無ければ作る）を使う。暫定方式の解の行は、[L0評価器の検査](../l0-evaluator-check/README.md)で作った
  `runs/p2-method-2026-10/l0-evaluator-check/b1_<s>bb`があるときだけ実行する。
- [run_b3.sh](run_b3.sh)は`runs/p2-method-2026-10/legacy-seed-noise/`の4つの解を読む。2つ目・3つ目の引数で評価用・fit用の
  配札数を変えられる（既定は2^24・2^23）。
- [summarize.py](summarize.py)（Python標準ライブラリだけ）はB1・B3の表を出力する。B1では、3つ目の引数のS4-1a2の結果と、
  同じ配札で測った量がbitで一致するかも確かめる。B3では評価用の配札数が違うので、L0の節だけを比べる。B3のfit用の配札数を
  変えた表と、thread数を変えた評価し直しの比較も出力する。

## 保持

[results/b1/](results/b1/)には、B1の9件のJSON（fitと評価、fit用の配札での評価）と、その集計・実行logを置く。
[results/b3/](results/b3/)には、B3のJSON（4つの解、fit用の配札数を変えた3本、8 threadの評価し直し）と、その集計・実行logを置く。

記録した。

  追記した。
